# 微信小游戏开发闭环

这套工具让你在 DSH 里完成微信小游戏的完整开发流程：浏览器预览 → 读日志排错 → 真机扫码 → 上传发布。

工具来自 MCP 服务 `minigame`，在会话里以 `mcp__minigame__*` 出现。

## 最重要的一条规则：改完代码必须自己预览

**只要你为用户生成、修改或调试了任何小游戏代码（`.js` / `.json` / `.css` / 图片资源等），代码写入完成后必须立即触发预览，不要等用户开口。**

DSH 会话标题栏**右上角**（Session log 按钮旁边）有一个「小游戏预览」按钮，左侧圆点是绿色就表示游戏正在运行。预览启动后，预览窗口会**自动弹出**，游戏画面直接出现在里面 —— 你不需要打开浏览器，也不需要把 URL 贴给用户。

判断用哪个工具：

- 本次会话**还没成功调用过** `mcp__minigame__run_game` → 用 `run_game` 启动
- 本次会话**已经启动过** → 用 `run_game` 热重载（它同时是启动和重载，幂等，直接调即可）

多个文件一起改完只需要重载**一次**，不要每改一个文件就重载。

## 启动 / 重载后的日志检查闭环

每次调用 `run_game` 之后，必须执行下面的循环，直到日志干净为止：

1. 等待约 2 秒，让游戏初始化
2. 调用 `mcp__minigame__get_logs`，用过滤条件只看错误：
   `"error|warn|Error|Warning|Uncaught|TypeError|ReferenceError"`
3. 分析结果：
   - **没有错误** → 循环结束，告诉用户游戏运行正常
   - **有错误** → 定位原因、修改代码 → 再次 `run_game` → 回到第 1 步
4. 重复，直到日志里没有错误

### 循环退出条件（防止无限重试）

修复过程中必须记录每个错误及其修复次数：

- **同一个错误**（相同的错误消息或相同根因）修复尝试超过 **5 次** → 暂停循环，把错误详情和已经试过的修复方案报告给用户，询问是否继续
- **不同错误累计**修复尝试超过 **15 次** → 暂停循环，汇总所有错误和修复尝试，询问用户是否继续
- 暂停时要讲清楚：已尝试的次数、错误列表、每个错误试了几次
- 用户选择继续时，计数器重置

## 项目结构要求

游戏目录必须包含 `game.js`（入口文件），这是预览的硬性前提。完整结构：

```
game-dir/
├── game.js                 # 入口文件（必须）
├── game.json               # 游戏配置
├── project.config.json     # 微信开发者工具项目配置（含 appid）
└── ... 其他资源
```

`run_game` / `real_device_preview` / `publish` 都需要传 `workspacePath`：游戏目录的**绝对路径**。

如果用户没有指定目录，先确认当前工作目录里是否有 `game.js`；没有就找子目录；仍然没有就自己生成一个最小可运行的工程再预览。

## 工具速查

| 工具 | 用途 | 关键参数 |
|---|---|---|
| `mcp__minigame__run_game` | 启动 / 热重载预览（幂等） | `workspacePath` |
| `mcp__minigame__get_logs` | 读游戏 console 日志 | `filter`（正则）、`lines`（只取最近 N 行） |
| `mcp__minigame__capture_screenshot` | 截图当前画面（Canvas2D / WebGL 都支持） | `format`、`output`（`data` 或 `path`） |
| `mcp__minigame__real_device_preview` | 生成真机预览二维码 | `workspacePath` |
| `mcp__minigame__publish` | 上传新版本到微信平台 | `workspacePath`、`version`、`desc` |

日志格式是 `[时间戳] [级别] 消息`。用 `lines: 50` 这类上限避免每次都把整个缓冲区拉回来。

**视觉验证**：改完画面相关的代码后，用 `capture_screenshot` 确认渲染结果，比只读日志更直接。需要多帧观察动画时可以用 `capture_screenshot_burst`。

## 真机测试

真机测试和上传都需要微信 **AppID** 和 **代码上传密钥**。

### 配置缺失时（工具返回 `configMissing`）

**必须引导用户配置，禁止使用任何替代方案**——不要跳过配置，不要用测试账号，不要用模拟数据，不要尝试绕过。

正确做法：

1. 告诉用户：「请在 DSH 的小游戏预览面板里点击右上角 ⚙️ 按钮，填写微信 AppID 和代码上传密钥。」
2. 引导获取密钥：微信公众平台 mp.weixin.qq.com → 管理 → 开发管理 → 开发设置 → 小程序代码上传
3. 等用户配置完成后再重新调用工具

### 已配置好时

直接调用 `mcp__minigame__real_device_preview`。二维码会在 DSH 的预览面板里以弹窗展示，告诉用户用微信扫码即可。

## 上传发布

1. 先和用户确认版本号（semver，如 `1.0.0`）和版本描述
2. 调用 `mcp__minigame__publish`，传 `workspacePath`、`version`、`desc`
3. 返回 `configMissing` → 按上面的配置引导处理
4. 成功后告知用户：新版本已上传到微信平台，需要登录 mp.weixin.qq.com 提交审核
5. 平台侧另有一组 `mp_*` 工具（`open_onboarding`、`mp_advance_step`、`mp_validate_step`、`mp_api` 等），
   覆盖小游戏的上线准备流程：填写游戏信息、备案与资质审核、提交版本、查询审核状态。
   用户提到「上线」「备案」「资质」「提交审核」时用它们；日常开发调试不需要。


## 各种情况下怎么引导用户

不要只说「失败了」。每个情况都要讲清三件事：**发生了什么、用户该做什么、你接着做什么**。

| 情况 | 对用户说什么 | 你接下来做什么 |
|---|---|---|
| 预览成功 | 「画面已在右上角的预览窗口里。如果没自动弹出，点右上角「小游戏预览」按钮即可，圆点变绿表示正在运行。」 | 继续读日志确认无报错，再收尾 |
| 用户说看不到画面 | 「点右上角「小游戏预览」按钮把窗口打开。」 | 用 `get_logs` 佐证游戏确实在跑；窗口没弹出不代表预览失败 |
| 圆点是灰的、窗口显示「预览未启动」 | 「预览服务当前没在运行。」 | 重新 `run_game`；仍然不行就问用户 `dsh web` 是否重启过 |
| 窗口显示「预览服务无响应」 | 「预览服务已经退出了。」 | 重新 `run_game` |
| 窗口显示「插件未挂载」 | 「预览插件没挂到这个界面上：请刷新页面；仍然不行就重启 `dsh web`。」 | 暂停调用预览工具，先等用户恢复，不要假装预览成功 |
| 你手上没有 `mcp__minigame__*` 工具 | 「当前会话没加载到小游戏工具。」 | 说明需要确认网络能拉取 npx 包并重启 `dsh web`；**不要用别的办法假装预览或截图成功** |
| 目录里没有 `game.js` | 「这个目录不是小游戏工程，请确认会话工作区或给出工程路径。」 | 拿到路径后重试；确实没有工程就按上面的结构生成一个最小可运行工程 |
| 日志里有报错 | 先别打扰用户，自己修 | 修复 → `run_game` → `get_logs`，直到干净；只在触发退出条件时才汇总上报 |
| 日志干净但画面不对 | 「日志没有报错，但画面看起来不对，我截图确认一下。」 | 用 `capture_screenshot` 做视觉核对，别只信日志 |
| 真机/上传缺配置（`configMissing`） | 「需要先在小游戏预览窗口右上角 ⚙️ 里填微信 AppID 和代码上传密钥。」 | 等用户配置完再重试；**禁止任何绕过方案** |
| IP 白名单（`-10008`） | 「本机公网 IP 不在白名单里，需要在微信公众平台更新。」 | 给出 mp.weixin.qq.com → 开发管理 → 开发设置 → 小程序代码上传 → IP 白名单 的路径，用户改完再重试 |
| 真机二维码 / 上传成功 | 「二维码在预览窗口里，请用微信扫码。」 | **不要重载、不要让用户刷新页面**，否则二维码消失 |

## 硬约束

> **`real_device_preview` 和 `publish` 成功之后，禁止再调用 `run_game`，也不要让用户刷新页面。**
>
> 二维码展示在预览面板的弹窗里，刷新或重载会让弹窗消失，用户就没法扫码了。
>
> 正常的代码改动（不是真机预览 / 上传之后）不受此限制，照常重载让用户看到最新效果。

> **IP 白名单错误（错误码 `-10008`）**
>
> 工具返回 `ipWhitelistError` 说明本机公网 IP 不在微信公众平台的白名单里。
>
> 正确做法：
> 1. 告诉用户：「你的本地公网 IP 可能变了，需要在微信公众平台更新 IP 白名单。」
> 2. 引导路径：mp.weixin.qq.com → 开发管理 → 开发设置 → 小程序代码上传 → IP 白名单
> 3. 预览页面右上角会显示当前公网 IP，可以让用户复制后添加
> 4. 用户更新白名单后重新调用工具

## 预览服务器

`run_game` 会在本机拉起一个预览服务器（默认 `http://localhost:3847`），并自动注入微信 `wx` API 兼容层，所以大部分小游戏 API 能在浏览器里模拟运行。它会监听工程目录，文件变化后重新打包并自动刷新已打开的预览页面——端口和 URL 在多次调用之间保持不变。

因此：**改完代码只需要调 `run_game`，不需要重启任何东西，也不需要通知用户手动刷新。**
